# Governance and community

English | [简体中文](index.zh-CN.md)

Governance keeps current instructions, compatibility promises, and historical
facts separate. Start with the page that matches your role:

| Role                     | Page                              | What it covers                                             |
| ------------------------ | --------------------------------- | ---------------------------------------------------------- |
| Contributor              | [Contributing](contributing.md)   | Setup, scoped changes, tests, and review evidence.         |
| Security researcher      | [Security](security.md)           | Private reporting, safe reproduction, and disclosure.      |
| Maintainer or integrator | [Compatibility](compatibility.md) | The 0.5.x window and migration boundaries.                 |
| Release owner            | [Releasing](releasing.md)         | Candidate checks, package order, and publication controls. |

Community entry points are [CONTRIBUTING.md](../../CONTRIBUTING.md),
[SECURITY.md](../../SECURITY.md), and [Support](../../SUPPORT.md). They never ask
for credentials or private logs. The [history index](../history/index.md) labels
preserved experiments, release notes, and attribution as historical evidence.
